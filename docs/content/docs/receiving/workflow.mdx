Receiving works through purchase orders that are on their way in. The dashboard
at `/receiving` gathers every order that is ready to be received, and each
order's page is where you count its line items into stock.

![Receiving dashboard](/modules/receiving/dashboard.png)

## Seeing what needs to be received

The receiving dashboard has two tabs:

- **Awaiting:** orders that still have goods to receive. An order appears here
  when its status is **Confirmed / Awaiting Delivery** or **Partially Received**.
- **Received:** orders that have been fully received. These are kept for
  reference and for reprinting labels.

Both tabs show the same columns:

| Column | Meaning |
| --- | --- |
| **#** | The purchase order's reference number. |
| **Supplier** | The supplier the order was placed with. |
| **Status** | Where the order sits in its pipeline, shown as a colored tag. |
| **Updated** | When the order last changed. |

You can filter by **Supplier**, and clicking a row opens that order's receiving
page.

<Callout>
  An order only shows up in receiving once it reaches **Confirmed / Awaiting
  Delivery**. Advance it that far from the purchase order itself; see
  [pushing a purchase order through the pipeline](/docs/purchasing/purchase-orders#pushing-a-purchase-order-through-the-pipeline).
  The purchase order's **Receiving** button warns you if the order is not yet at
  that stage.
</Callout>

The home dashboard also carries a **Receivable POs** panel that lists the same
awaiting orders, so incoming deliveries are visible without opening the module.

## The order's receiving page

Opening an order shows three sections:

- **Expected:** the lines still on their way. This is where you start a
  receipt.
- **Deliveries:** every delivery received against the order, with the
  inspection result, the lots it created and anything that still needs a look.
- **Received:** the received lines, where you can reprint
  [labels](/docs/receiving/labels).

### The item name shown

Suppliers often refer to an item by their own name or catalogue code. When a
[supplier alias](/docs/inventory/items#aliases) exists for this order's supplier
and item, receiving shows the supplier's name, since that's what is on the
shipment, with your item name underneath.

## Receiving a delivery

The receiving screen is built for a tablet at the dock. Tap the lines that
arrived under **Expected**, then **Receive**. A full-screen flow walks through
the delivery:

1. **Delivery.** The packing slip number, carrier, and a photo or PDF of the
   packing slip or bill of lading (all optional). Check the outside of the
   pallets before signing for the freight.
2. For each line in the delivery:
   - **Inspect.** Answer each check: right item, packaging intact, seals
     intact, supplier labels, count matches the slip. **Everything looks OK**
     answers them all at once. A **Problem** asks what's wrong, and a photo is
     encouraged. It doesn't stop the receipt; the line is flagged.
   - **Supplier lots.** One row per supplier lot in the delivery, with the
     supplier's lot number as printed on the container, the quantity in the
     purchase unit, and optionally the expiry (or retest) and manufacture
     dates. Each row becomes its own lot here with its own labels. The total
     shows how it compares with what was expected.
   - **Documents.** What the item's [document
     requirements](/docs/inventory/item-documents) expect for a received lot,
     usually the COA. Documents already on file for the supplier lot (for
     example a COA the supplier emailed ahead) are matched and attached
     automatically. Photograph or upload paperwork that came in the box. Item
     documents that need attention, like an expired SDS, are listed too.
3. **Review**, then **Receive**. Afterwards, print labels straight from the
   confirmation.

### Nothing blocks a receipt

Problems are recorded and flagged on the delivery and the lot instead of
stopping the receiver:

| Flag | Meaning |
| --- | --- |
| **Inspection issue** | A check failed at the dock. The note and photos are on the delivery. |
| **More than ordered** | More arrived than was still expected on the line. |
| **Rest still expected** | Less arrived; the remainder stays open on the order. |
| **No supplier lot** | The supplier's lot number wasn't recorded. |
| **Docs missing** | A required lot document (e.g. the COA) isn't on file yet. |
| **COA lot mismatch** | A document on the lot names a different supplier lot. |

The document flags are worked out from what's on file now, so they clear by
themselves once the right document is filed. Agents can list recent flagged
deliveries with [`get_receiving_issues`](/docs/mcp#receiving-alerts).

### What the order does

- A line with several supplier lots is split into one line per lot, so each
  line keeps exactly one lot.
- Receiving less than expected leaves the rest on a new line that stays on the
  Awaiting tab for the next delivery. Expected delivery dates carry over.
- When nothing is left to receive the order moves to **Received**, otherwise
  to **Partially Received**.

<Callout>
  Receiving also updates any [procurement
  requests](/docs/purchasing/procurement-requests) linked to the order, marking
  them Delivered or Partial Delivery so the original requester can see progress.
</Callout>

## Units and conversions

An order records quantities in the unit the supplier sells in, which is not
always the unit you stock the item in. Receiving reconciles the two: when the
purchase unit differs from the item's inventory unit of measurement, the
received quantity is converted into the inventory unit before the lot is created.

Lumexia converts using either a standard conversion (for SI or imperial units)
or a supplier-specific [discrete
conversion](/docs/inventory/item-details#discrete-conversions) (for pack units
like a case, tote, or drum). For the full picture of how conversions are
defined, see [Unit of Measurement
Conversions](/docs/inventory/uom-conversions).

If no conversion exists for the units involved, the line cannot be received and
shows a red **Set up conversion** button instead. Clicking it opens the discrete
conversion form for that item and supplier, pre-filled with the purchase unit;
once you save the conversion (for example, `1 drum = 450 lb`), return to
receiving and the line can be received normally.

## The lots that result

Each supplier lot received becomes a new [lot](/docs/inventory/item-details#lots)
of the item:

- The lot's quantity is stored in the item's **inventory unit of measurement**,
  after any conversion above.
- A [lot number](/docs/inventory/lot-numbers) is generated automatically from the
  item's reference code and the date.
- It keeps the **supplier lot**, expiry and manufacture dates entered at the
  dock, and records its origin as this purchase order and delivery.

The lot's **Receiving** card on the item page shows how it came in (who received
it, the inspection, photos and flags) and lets you correct the supplier lot or
dates later. Setting a supplier lot there also attaches any documents that were
waiting for it.
