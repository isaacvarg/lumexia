The quality module does two things: it **defines standardized specifications** for each
item, and it **records the results** of testing samples. The first is a
setup activity (parameters and specifications); the second is a day-to-day one
(examinations against lots), and Lumexia checks results against the
specifications to decide pass or fail.

## The pieces

- **Parameters** are the measurable characteristics you test, such as pH, assay,
  or appearance. A parameter has a data type and can carry extra sub-inputs.
- **Specifications** attach parameters to a specific item and set the acceptable
  values, so an item knows what a passing result looks like for each parameter.
- **Examinations** are recorded test events against a [lot](/docs/inventory/lot-numbers).
  You enter measured values and Lumexia evaluates each one against the item's
  specification.
- **Micro** submissions generate a lab sample submission form for outsourced
  microbiological testing.

The quality area is reached at `/quality/qc`, with a separate **Micro** area at
`/quality/micro`. You can also start an examination by scanning a lot.

<Callout>
  In the interface a recorded test event is always called an **examination**.
</Callout>

## Where quality connects

Quality ties into the rest of Lumexia through lots and produced batches:

- Every examination is recorded against a [lot](/docs/inventory/lot-numbers), and
  an item's [Quality tab](/docs/inventory/item-details#quality) shows its
  parameters, specifications, and results.
- A produced batch's [Quality tab](/docs/production/planning) lists the
  examinations conducted for that batch.
- A [Certificate of Analysis](/docs/quality/examinations#certificate-of-analysis)
  for a finished lot is built from its specifications and results.
